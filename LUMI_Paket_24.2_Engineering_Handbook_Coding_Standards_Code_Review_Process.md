# Project LUMI -- Paket 24.2

# Engineering Handbook, Coding Standards & Code Review Process

## Amaç

LUMI geliştirme ekibinin aynı mühendislik standartlarını uygulamasını,
kod kalitesini korumasını ve sürdürülebilir bir geliştirme süreci
izlemesini sağlamak.

## Mühendislik İlkeleri

-   Basit ve okunabilir kod
-   Modüler tasarım
-   SOLID prensipleri
-   DRY (Don't Repeat Yourself)
-   KISS (Keep It Simple)
-   YAGNI (You Aren't Gonna Need It)

## Kodlama Standartları

-   TypeScript strict mode
-   ESLint ve Prettier
-   Tutarlı isimlendirme
-   Küçük ve odaklı fonksiyonlar
-   Anlamlı yorumlar

## Branch Stratejisi

-   main
-   develop
-   feature/\*
-   hotfix/\*
-   release/\*

## Commit Kuralları

Önerilen yapı:

-   feat:
-   fix:
-   refactor:
-   docs:
-   test:
-   chore:

Semantic Commit mesajları kullanılmalıdır.

## Code Review Süreci

Her Pull Request için:

1.  Otomatik testler başarılı
2.  Statik analiz temiz
3.  En az bir teknik inceleme
4.  Mimari standartlara uygunluk
5.  Dokümantasyon güncelliği

## Kalite Kapıları

-   Birim testleri
-   Entegrasyon testleri
-   Lint kontrolü
-   Güvenlik taraması
-   Performans kontrolü

## Test Senaryoları

-   Kod standartlarına uygunluk
-   Commit formatı doğrulaması
-   PR doğrulaması
-   Kod inceleme süreci
-   Kalite kapısı doğrulaması
