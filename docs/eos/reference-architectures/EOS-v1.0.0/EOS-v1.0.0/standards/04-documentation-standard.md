# 04 — Documentation Standard

**Document ID:** EOS-STD-004  
**Version:** 1.0.0  
**Status:** Approved

## Purpose

Ensure documentation is structured, current, searchable, and useful.

## Document Categories

- Governance
- Planning
- Architecture
- Development
- Testing
- Release
- Operations

## Mandatory Metadata

- Document ID
- Version
- Owner
- Status
- Last Update
- Related Documents, when applicable

## States

Draft → Review → Approved → Archived

## Required Practices

- Use Markdown unless another format is justified.
- Use kebab-case file names.
- Keep one authoritative copy.
- Update documentation with related product changes.
- Archive obsolete documents instead of silently deleting history.

## Recommended Structure

Purpose → Principles → Required Practices → Anti-Patterns →
Deliverables → Quality Checklist → Exit Criteria

## Anti-Patterns

- Duplicate authoritative documents
- Unversioned standards
- Documents without owner or status
- Documentation that contradicts implementation

## Exit Criteria

A document is complete when required metadata exists, content is reviewed, and its status is Approved.
