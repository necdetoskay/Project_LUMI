# 01 — Project Lifecycle

**Document ID:** EOS-STD-001  
**Version:** 1.0.0  
**Status:** Approved

## Purpose

Define the mandatory lifecycle used by EOS projects.

## Lifecycle

Idea → Discovery → Design → Planning → Design Freeze → Execution →
Stabilization → Release → Maintenance

## Required Practices

- Each project declares its current lifecycle stage.
- Entry and exit criteria are documented.
- Mode transitions require the related Quality Gate.
- New scope discovered during Execution is added to backlog.

## Anti-Patterns

- Coding before problem and architecture are understood.
- Returning to Design for non-critical preferences during Execution.
- Releasing directly from active feature development.
- Treating Maintenance as an unstructured period.

## Deliverables

- Lifecycle status
- Stage outputs
- Gate evidence
- Transition approval

## Quality Checklist

- Current stage is known.
- Required outputs exist.
- Risks and dependencies are visible.
- Transition decision is recorded.

## Exit Criteria

The current lifecycle stage ends only after its required Quality Gate passes.
