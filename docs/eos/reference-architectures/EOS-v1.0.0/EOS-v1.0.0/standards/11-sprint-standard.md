# 11 — Sprint Standard

**Document ID:** EOS-STD-011  
**Version:** 1.0.0  
**Status:** Approved

## Purpose

Standardize short, focused delivery cycles.

## Principles

- Goal First
- Fixed Scope
- Small Increments
- Transparency
- Definition of Done

## Lifecycle

Backlog → Planning → Execution → Quality Gate → Review → Retrospective

## Required Practices

- Define one Sprint Goal.
- Select work that supports the goal.
- Make acceptance criteria explicit.
- Identify dependencies and risks.
- Track progress and blockers.
- Complete review and retrospective.
- Move unfinished work back to backlog; do not silently carry it.

## Roles

- Product: value, priority, acceptance
- Engineering: implementation, technical quality
- AI Agent: assigned assistance under EOS rules

## Anti-Patterns

- Changing the Sprint Goal mid-sprint
- Adding uncontrolled scope
- Skipping tests or review to meet a date
- Treating activity as completion

## Deliverables

- Sprint Goal
- Sprint Backlog
- Working Increment
- Test Evidence
- Review Notes
- Retrospective Notes

## Exit Criteria

A sprint closes when the goal is evaluated, completed work meets Definition of Done, and remaining work is explicitly handled.
